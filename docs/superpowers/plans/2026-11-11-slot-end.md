# A Routine Slot's End — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A routine slot can hold one chosen end position (like a free figure's length per slot); seams, the picker and the slot's line read the slot's effective end; back closes an open slot or a selection.

**Architecture:** One nullable column `routine_steps.end_position_id` (a real `positions.id`). A new pure module `src/lib/routines/end.ts` decides each slot's effective end and its state from the slot's options, the stored end and the starts of the slot below; `routines.ts` feeds that into `RowEdges.ends` so every existing reader (seams, picker, run) follows. The server writes through `setSlotEnd`; copies map it like a position; the editor shows a chip / accent text / dashed chip and an `EndSheet`.

**Tech Stack:** SvelteKit 2 / Svelte 5 runes, Drizzle + SQLite (server and the phone's WASM copy run the same code), vitest, Tailwind v4, Playwright shots rig.

**Spec:** `docs/superpowers/specs/2026-11-11-slot-end-design.md` (board https://claude.ai/artifact/DrF5T6kTJ4p5ka6qfVmeN4)

## Global Constraints

- Additive `ADD COLUMN` only, no CHECK; `npm run db:generate`; read the generated SQL (migration 0052).
- `routine_steps` is already synced with row-level triggers: no trigger migration.
- Server time through `serverNow()`; data functions take `db` first; specs use `openDb(':memory:')`.
- A group mutation: `logChange` (via `logRoutine`) in its transaction, listed in `changes.spec.ts` `MUTATIONS`.
- Own rows point at group rows only via `usableOf`; `crossRefs(db)` must stay `[]` (new `REFS` entry).
- Every write classified in `src/lib/offline/routes.ts` (`end: 'device'`, like `length`).
- Words through `t()`, both catalogs (en, sl, vikanje); `no-english.spec.ts`, `refusals-guard.spec.ts`.
- A built control's colour is the builder's: no `text-*` appended to `LENGTH_CHIP`; new chip looks are new builders in `styles.ts`.
- Slot rules (CLAUDE.md): per task run only its specs (`npx vitest run <files> --maxWorkers=4`), `npx eslint` + `npx prettier --check` on changed files; full `npm run check` before the final review and after merging master; never `vite build` alone.
- Copy (exact): title »Kje konča?« / "Where does it end?"; ask chip »Konča?« / "Ends?"; clear »Ne izberem — katerikoli konec« / "No choice — any end"; »Alternativa {name} ne konča tu« / "Alternative {name} doesn't end here"; »Mesto {n} ne začne tu« / "Slot {n} doesn't start here"; refusal »Ta konec ne ustreza temu mestu.« / "That end doesn't fit this slot."

## Review Focus

1. A twinned hold: the stored end is the person's real id, the graph is canonical — a choice must survive (`g.canon`). Test in Task 2.
2. A person's routine holding a group figure whose end is a group position: the write is allowed, `crossRefs` stays `[]`. Test in Task 4.
3. The slot below is an embedded routine or an archived-only slot: rule 3 uses the next danceable row's starts. Test in Task 3.
4. Copying a routine into a place with no member of the end's family: the copy's end is null, not a dangling id. Test in Task 5.
5. An older phone page (no `end` field in the data) must still render: every new field optional on the page. Covered by Task 7's `slotMeta` tests with `endState` absent.

### Task 2: `end.ts` — shared ends, effective end, choices

**Files:**
- Create: `src/lib/routines/end.ts`, `src/lib/routines/end.spec.ts`

**Interfaces:**
- Consumes: `Graph`, `figureById`, `OptionsSlot.end`, `Graph.canon`.
- Produces:
  - `type EndState = 'none' | 'single' | 'decided' | 'chosen' | 'open'`
  - `interface SlotEnd { ends: number[] | null; state: EndState; stored: number | null }` — `ends` canonical ids; `stored` the canonical stored end when valid, else null.
  - `sharedEnds(g: Graph, slot: OptionsSlot): number[] | null` — intersection (canonical, ascending) of the options' ends, ignoring options with no ends; `[]` when no option has ends; `null` when options have ends but share none.
  - `slotEnd(g: Graph, slot: OptionsSlot, below: number[] | null): SlotEnd` — the spec's rules 1–5 in order; `below` = starts of the slot below (`null` = no slot below; `[]` = enters anywhere, decides nothing). `C` null → `{ends: null, state: 'open'}`.
  - `endFits(candidateEnds: number[], slotEnds: number[] | null, mainEnds: number[]): boolean` — an alternative's ends fit: `slotEnds` of length 1 (`E`) → `candidateEnds` empty or includes `E`; otherwise `sameSet(candidateEnds, mainEnds)`.
  - `interface EndChoice { id: number; blockedBy: number | null; belowMisses: boolean }` and `endChoices(g: Graph, slot: OptionsSlot, below: number[] | null): EndChoice[]` — one per end of the main figure (canonical, in the main figure's order); `blockedBy` = the first alternative figure id whose non-empty ends lack it; `belowMisses` = `below` non-empty and lacks it.

- [ ] **Step 1: Failing tests** (fixture graph: positions A=1, B=2, X=3; figures M ends [1,2], N ends [1,2], K ends [1,3], Z ends [], S1 starts [1], S12 starts [1,2]):

  - `slotEnd` rules: [Z] → `{state:'none', ends:[]}`; [K-only-with-one-end] → `single`; [M] below [1] → `{state:'decided', ends:[1]}`; [M] stored 2 below [1] → `decided` [1] (stored overridden, `stored: 2`); [M] stored 2 below [1,2] → `chosen` [2]; [M] stored 3 → `open` [1,2], `stored: null`; [M] below null → `open`; [M] below [] → `open`.
  - `slotEnd uses g.canon for the stored end`: `g.canon = new Map([[9, 2]])`, slot end 9 → `chosen` [2], `stored: 2`.
  - `endFits`: ([1,3], [1], [1,2]) true; ([3], [1], [1,2]) false; ([], [1], [1,2]) true; ([1,3], [1,2], [1,2]) false; ([2,1], [1,2], [1,2]) true.
  - `endChoices` for [M,K] below [2]: `[{id:1, blockedBy:null, belowMisses:true}, {id:2, blockedBy:K, belowMisses:false}]`.
