# The map: walk sheet and walking a routine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace today's Positions map (circles in a card) with a full-screen map of name pills, a sheet that steps from position to position, and a walk that builds a routine.

**Architecture:** The server sends the map's layout once, with the figures on every arrow. Everything a tap changes (what is lit, the sheet's rows, the walk, the view's pan and zoom) is worked out by PURE modules in `src/lib/positions/` and drawn by thin components. The layout never runs on a tap.

**Tech Stack:** SvelteKit 2 + Svelte 5 runes, TypeScript, Tailwind 4, vitest, Drizzle/SQLite.

**Spec:** `docs/superpowers/specs/2026-11-08-map-walk-design.md`. Read it first. It links the mockups: A and C on the third page are the look to match. The mockup source is in this session's scratchpad: `big/des.part` and `big/help.part` (look, sizes and fades), not code to copy.

## Global Constraints

- Words go through `t()`, in both catalogs (en, sl). New and changed components go in `TRANSLATED` (`src/lib/i18n/no-english.spec.ts`). Slovenian uses vikanje, plurals through `slCount`, and the glossary at the top of `sl/index.ts`: Position = položaj, Routine = kombinacija, a figure = različica, a move = figura.
- Colours only from tokens: `--color-accent` for out and the walk, `--color-easy` for in and the step just taken, `--color-danger` for gaps, type tones via `TONE_VAR`/`styleTone`.
- PURE modules (`map.ts`, `map-view.ts`, `map-fit.ts`, `map-sheet.ts`, `walk.ts`) have no DOM, no clock and no randomness, and run under the node vitest project.
- The layout runs once per load (server, in `mapData`), never on a tap.
- Nothing under `$lib/server` is imported by components. The shared shapes live in `map-view.ts` (client-safe).
- A form someone fills in (the routine's name) uses `use:guarded`.
- Raise `PAGE_EPOCH` only if an existing form or action changes shape. Adding a new action needs no raise.
- `npm run check` must pass at the end of every task. Run it through `nix develop -c`.

## Review Focus

1. **A busy position** (13+ places, as Open, two hands in the mockup): the sheet scrolls, every place is listed, and the fitted view is never smaller than the map's whole-map scale. Test in Task 3 (`fitView` floor) and Task 4 (rows).
2. **A figure with several starts and several ends** shows once per (start, end) pair. It is listed under each place it reaches, and in a walk it lands where that place's chip says. Tests in Task 4 and Task 5.
3. **The same figure walked twice**: the badge reads "2,5", and the saved routine keeps both slots in order. Tests in Task 5 (`walkedArrows`) and Task 1 (`orderedInts`).
4. **Twins and group mode**: a twinned node's figures come from the folded graph, and group mode has no gap chips in the tray. Test in Task 1 (twins) and Task 7 (tray chips hidden in group mode).
5. **Nothing to draw** (no positions, or positions but no arrows): the old empty and unjoined texts still show, with the tray, and no sheet can open. Test in Task 7.

### Task 5: The walk's model

**Files:**
- Create: `src/lib/positions/walk.ts`, `src/lib/positions/walk.spec.ts`

**Interfaces:**
- Consumes: `MapData`, `MapFig`, `edgeKey`.
- Produces:
  ```ts
  export type WalkStep =
    | { kind: 'figure'; fig: MapFig; from: number | null; to: number | null }   // from null: after a no-end figure
    | { kind: 'jump'; to: number };                                             // the tap after a no-end figure
  export interface Walk { start: number; steps: WalkStep[] }
  export function currentOf(w: Walk): number | null;          // null right after a no-end figure
  export function figureCount(w: Walk): number;
  export function addFigure(w: Walk, fig: MapFig, to: number | null): Walk;
  export function jumpTo(w: Walk, id: number): Walk;          // only when currentOf is null; otherwise returns w unchanged
  export function undo(w: Walk): Walk;                        // drops the last step, jump or figure
  export interface NextGroup { to: number | null; stays: boolean; figs: MapFig[] }  // to null: Anywhere (no end)
  export function nextFrom(data: MapData, at: number): { groups: NextGroup[]; fitsAnywhere: { fig: MapFig; to: number | null }[] };
  // groups: one per drawn edge out of `at` (most figures first, a stay first among equals), then Anywhere when anyFrom has any.
  // fitsAnywhere: every noStart figure, once per end (or once with to null when it has none).
  export function walkedArrows(w: Walk): Map<string, { from: number; to: number; numbers: number[] }>;
  // keyed by edgeKey; figure steps with both from and to only; numbers are the figure's 1-based count among figure steps.
  export function visited(w: Walk): Set<number>;
  export function figureIds(w: Walk): number[];              // in order, repeats kept
  ```

- [ ] **Step 1: Write failing tests:**

  - `undo` removes a jump on its own.
  - `figureIds` keeps repeats: `[5, 7, 5]`.
  - `nextFrom` lists a stay group first among equal counts, puts Anywhere last, and gives `fitsAnywhere` one entry per end.
  - A fits-anywhere figure walked at A to end E is in `walkedArrows` under `'A:E'`, even when the data has no A → E edge. Task 7 draws it dashed.
