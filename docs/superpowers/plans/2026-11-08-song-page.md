# The song page: listening, Edit, sections — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the song page into a minimal listening view and an Edit mode (Grid and Song tabs) that saves as you go. Add song sections (named, on a 1, count on or off) and downbeat suggestions. Have every song start where its music starts.

**Architecture:** Three new PURE modules hold the rules: `sections.ts` (parse, snap, grid rows, what's next), `suggest.ts` (downbeat suggestions) and `music-start.ts` (the effective start, where Play begins). The server stores three new `songs` columns. Every write goes through `editSong` (History, the clash check) and the page's `flowing` actions (Keep in step). The page owns the one `<audio>`. Listening and Edit are two views on it, and Edit is page state registered with the sheet stack so Back leaves Edit first. The home worker measures the music start from the WAV it already makes.

**Tech Stack:** SvelteKit 2 + Svelte 5 runes, SQLite/Drizzle, Vitest, Tailwind 4, Python 3.11 worker (pytest), Playwright shots rig.

**Spec:** `docs/superpowers/specs/2026-11-08-song-page-design.md` (read it whole first). The board is https://claude.ai/artifact/YPLPyKeSZ78HJyDAkE8kyz (rows 1–5 are the screens).

## Review Focus

1. **A bad `sections_json`** (`''`, `'null'`, `'{}'`, an entry with `at: "x"`, `NaN`, a negative `at`, a 300-character name). It reads as no sections, or drops the bad entries, everywhere: the load, the flat fields, the copy. Never a 500. Tests: Task 3 (`parseSections`) and Task 2 (`songFlat` of a bad value).
2. **A count change that crowds sections.** At ×½ a 4-beat Break and the next section want the same 1: none is lost, the later one moves on, and ×1 puts both back where they were. Test: Task 3 (`placeSections` at ×½ and back).
3. **Undo or a section write on a group's song with a stale `seen`** (someone else changed it meanwhile). It is a 409 clash naming who changed it, and the page reloads. It is never a quiet overwrite. Test: Task 7 (`restore` and `sectionAdd` with an old `seen`).
4. **Anchors and downbeats that don't fit the beats**: an anchor index past the end after a re-analysis, empty `downbeats_json`, null `beats_json`, fewer than 4 beats. Suggestions are `[]`, the rows still draw, nothing throws. Test: Task 4 and Task 3 (`gridRows` with stray anchors).
5. **A music start that can't be right**: the worker sends `-1`, `NaN` or a value past the song's length, or the person's start is past the end. It is refused (400, or `false` from the data function). Play from 0:00 never seeks past the end. Tests: Task 1 (`setMusicStart`), Task 5 (`parseAnalysis`, the start route, `playFrom`).

```ts
export const SECTION_KEYS = ['intro', 'verse', 'coro', 'montuno', 'mambo', 'break', 'outro'] as const;
export const SECTION_NAME_MAX = 40;
export interface Section { at: number; name: string; countOff: boolean }
/** A section as drawn: on a 1 of the current count. `index` is its place in the stored list. */
export interface Placed extends Section { index: number; beat: number; t: number }
export function parseSections(json: string | null | undefined): Section[];
export function sectionsJson(list: Section[]): string;
export function sectionName(s: { name: string }): string; // '' → t().songs.page.section.unnamed
export function placeSections(list: Section[], beats: number[], counts: number[]): Placed[];
export interface Row {
	start: number; end: number; t: number;      // beat indices [start, end), the start's time
	lead: boolean;                               // the part before the first 1
	short: number | null;                        // its length when < 8 and not lead or last
	section: number | null;                      // index into placed, on the row a section starts on
	quiet: boolean;                              // starts before the music start (≥ MUSIC_START_MIN_S)
}
export function gridRows(beats: number[], counts: number[], placed: Placed[], musicStartS: number): Row[];
export function sectionIndexAt(placed: Placed[], beat: number): number; // into placed, -1 before the first
export interface Ahead { next: Placed; beatsLeft: number; eightsLeft: number; mode: 'eights' | 'last' | 'beats' }
export function aheadOf(placed: Placed[], counts: number[], beat: number): Ahead | null;
export function aheadLine(a: Ahead): string; // "Mambo in 3 eights" · "Mambo after this eight" · "Montuno in 2 beats"
export type SectionRefusal = 'taken' | 'ends' | 'missing';
export function addSectionAt(list: Section[], placed: Placed[], beats: number[], beat: number): Section[] | 'taken';
export function moveSection(list: Section[], placed: Placed[], beats: number[], counts: number[], index: number, dir: -1 | 1): Section[] | SectionRefusal;
export function editSection(list: Section[], index: number, patch: { name?: string; countOff?: boolean }): Section[] | 'missing';
export function removeSection(list: Section[], index: number): Section[] | 'missing';
```

Rules the tests pin (the spec, "Sections: data and rules"):
- `parseSections` keeps the entries with a finite `at ≥ 0`, a string `name` (trimmed, cut to 40) and a boolean `countOff`, sorted by `at`. Anything else in the JSON reads as `[]`. It never throws.
- `placeSections` goes in time order. Each section snaps to the 1 (`counts[i] === 1`) nearest its `at`, among the 1s after the previous placed section's beat. A section with no 1 left is not placed.
- `gridRows` starts a row at beat 0 and at every 1. `musicStartS` below `MUSIC_START_MIN_S` marks nothing quiet. This task creates `src/lib/songs/music-start.ts` holding only `export const MUSIC_START_MIN_S = 1;`, and Task 5 fills it in.
- `aheadOf` gives the next placed section after `beat` (from `sectionIndexAt + 1`, or the first one before any). `eightsLeft` is the number of 1s in `(beat, next.beat]`. `mode` is `'beats'` while the current section is count off, `'last'` when `eightsLeft === 1`, else `'eights'`. It is null when nothing is ahead. (My call, refining the spec's "under 8 beats": a counted section reads in eights and its last eight reads "after this eight"; a count-off section reads in beats.)
- `addSectionAt` is refused with `'taken'` when a placed section already sits on `beat`. Otherwise it adds `{ at: beats[beat], name: '', countOff: false }`.
- `moveSection` moves a section to the 1 eight beats away, or the nearest 1 beyond that in the same direction. It is refused with `'ends'` past the song's ends, `'taken'` onto or past a neighbour's beat, and `'missing'` for a bad index. The moved section's `at` becomes that 1's time.

**Files:**

- Produces:

```ts
export const SUGGEST_MIN_RUN: number; // N, tuned in Step 5 (start at 4)
export interface Suggestion { beat: number; t: number; shift: number } // beat in the scaled beats; shift in counted beats, signed (+ later)
export function suggestions(input: {
	raw: number[];        // the stored ×1 beats
	downbeats: number[];
	beats: number[];      // scaled to the tempo factor
	counts: number[];
	anchors: number[];
	placed: Placed[];
	minRun?: number;
}): Suggestion[];
```

The rule (the spec, "Suggestions: the rule"):
- Map each downbeat to its nearest raw beat within a quarter of the median interval. Its phase is that index mod 4.
- The count's phase at raw beat j comes from the last 1 of the count at or before j, mapped to raw the same way. Where a 1 sits between raw beats (a ×2 midpoint), there is no count phase and no suggestion in that stretch. (My call, replacing "turn them off at ×2 if they flood": nothing can flood, and the doc gets the new wording in Task 13.)
- Downbeat runs of the same phase shorter than `minRun` are noise and are skipped. Neighbouring qualifying runs of one phase merge.
- A qualifying run whose phase differs from the count's phase at its first downbeat suggests that downbeat's beat. Skip it when it maps to no scaled beat within tolerance, falls within 8 scaled beats of an anchor, sits inside a count-off placed section, or already has count 1 or 5.
- `shift` is the signed distance in scaled beats to the nearest beat counted 1 or 5.
