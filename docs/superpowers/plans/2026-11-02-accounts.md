# Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the app admin invite friends who each get a private copy of the app, with a storage limit per person, What uses space, Ask for more, and an admin page.

**Architecture:** A `Wall` (`{ userId, dance }`) replaces the bare `DanceSlug` wherever data is scoped, so the dance wall and the new owner wall are one thing and the compiler finds every call site still scoped by dance alone. Root content tables get a `user_id`; child rows derive their owner through their parent exactly as they derive their dance. Invites, storage and the admin page are new modules beside it.

**Tech Stack:** SvelteKit 2 / Svelte 5, TypeScript, Drizzle + better-sqlite3, Vitest, Tailwind 4, the `qrcode` npm package (new).

**Spec:** `docs/superpowers/specs/2026-11-02-accounts-design.md` — read it first. Also `CLAUDE.md` (hard rules), `src/lib/server/scope.ts` (the dance wall this extends) and `src/routes/[dance]/dance-wall.spec.ts` (how the wall is tested).

## Global Constraints

- All commands run inside the dev shell: `nix develop -c <cmd>`. `npm run check` (prettier + eslint + svelte-check + build + vitest) must pass at the end of every task.
- Never add a CHECK to an existing table; additive `ALTER TABLE ... ADD COLUMN` only. Read the generated SQL before committing. Dropping/creating an index is fine.
- Data functions take `db` first. Specs use `openDb(':memory:')`; a spec that needs `getDb()` mocks `$lib/server/db` as `dance-wall.spec.ts` does. No spec touches `$DATA_DIR`.
- Nothing under `$lib/server` is imported by components; shared row shapes go in `src/lib/types.ts`.
- Another person's row and a missing row get the same 404 (same message as the dance wall gives today).
- `src/lib/day` and `src/lib/urgency` never learn about users.
- Default storage limit for a new account: `DEFAULT_STORAGE_LIMIT_BYTES = 1024 ** 3` (1 GiB). The admin's limit is `null` (no limit).
- Invite lifetime: `INVITE_TTL_MS = 24 * 60 * 60 * 1000`. Shown once; only its SHA-256 is stored.
- Copy (exact): Join refusal "This invite no longer works. Ask for a new one."; Sign in hint "Got an invite? Open its link, or scan its code with your camera."
- UI uses the shared components in `src/lib/components/ui/` and the class builders in `ui/styles.ts`; follow the colour rules in CLAUDE.md (`class-rules.spec.ts`). Forms people fill in use `use:guarded`; one-tap forms use `use:enhance`.
- Commit at the end of each task, message `feat(accounts): …` / `test(accounts): …`, ending with:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01Narn2YPMsGjhR4rVYY1Guh
  ```
- Agents: never run commands that read endless input (no `script`, no `/dev/zero`, `/dev/urandom` only via `head -c`), never leave a server running, never touch `.data/` or `~/Backups`.

## Review Focus

1. **A create path that forgets the owner.** Every insert into a root table (figures and their groups, exercises — including the ones made for a lesson review, a routine, a figure — songs from upload, URL and the worker, lessons, routines, count takes, create-and-link in the Link popup, `createRoutineFromFigures`, a YouTube save landing as a recording or lesson video) sets `userId`. A row without one is invisible to its owner. Each area task's spec asserts the created rows carry the wall's `userId`.
2. **Flat routes and media files.** `/api/video-spots*`, `/api/figures/[id]/recordings`, `/api/lessons/[id]/videos/[uploadId]`, `/api/songs`, `/api/count-takes`, and the four media servers have no dance in the URL. Another person's id or file name must 404 — tested in each owning task.
3. **Cross-links between people.** Linking person B's figure, routine, exercise or song into person A's lesson, routine or exercise (ids in a form body) must 404 and change nothing, exactly as a cross-dance id does today.
4. **An invite redeemed twice at once.** Two Join posts with the same code: exactly one account; the second gets the refusal copy. Tested in Task 7.
5. **A chunked upload that declares a small total and keeps going.** The storage check uses the declared total at the start; `writeChunk` already refuses bytes past the declared total — Task 8's spec asserts an over-limit declared total gets 413 and leaves no partial file.

The next five tasks convert one area each to the `Wall`. They share one recipe; each task lists its files and its extra rules.

**The recipe (every area task):**
1. Every exported data function in the area's modules that takes `dance: DanceSlug` takes `wall: Wall` instead, in the same position, and filters by **both** `dance` and `userId` on the root table (children through their parent's join, as the dance is filtered today). Every insert into a root table sets `userId: wall.userId`.
2. Every comparison of a row's `dance` with the request's dance, or of two rows' dances (`a.dance === b.dance`, `found.dance !== dance`), becomes `inWall(row, wall)` or a comparison of both `dance` and `userId`. `grep -n '\.dance\b'` over the area's modules and routes must show no dance-only comparison left.
3. The area's `require*InDance` guards in `scope.ts` become `require*InWall(db, wall, id)` (same 404 messages); all callers change; the old name is deleted.
4. Routes: `const wall = wallOf(params, locals)` replaces `danceOf(params)`; flat routes (no `[dance]`) check the row's owner against `locals.user.id` with the same 404.
5. Update the area's existing specs to pass walls from `test-walls.ts` (`U1_SALSA` where they passed `'salsa'`).
6. Add the area's section to `src/routes/[dance]/owner-wall.spec.ts` (create it in Task 2 by copying the harness at the top of `dance-wall.spec.ts`: the `getDb` mock, `post`, `loadAt`, `refuses`), with `locals.user` = user `u2` acting on rows made by `u1` **in the same dance**: every load and action of the area that takes an id refuses with 404 and the row is unchanged, and every list load shows none of u1's rows. 7. `npm run check` passes; commit.
