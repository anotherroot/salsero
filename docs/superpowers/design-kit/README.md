# kit — the C4 look as Python building blocks

Pure Python 3 stdlib. Every function returns an HTML string: inline styles only,
every element closed (SVG children too), every attribute quoted, real
buttons/inputs/labels, `aria-label` on icon buttons. Board = `canvas/project/DesignSystem.dc.html`
(generated by `system.py`); the approved screens redrawn = `examples.py` (copy its pattern).

```python
import sys; sys.path.insert(0, '/tmp/claude-1000/-home-tilen-Projects-salsaapp-wt-app-icons/cf18291b-f44a-483d-bf97-2da9a238a117/scratchpad/gen/kit')
import kit

def lessons(t):                                   # one screen = one function of the theme
    header = kit.band_header(t, 'Lessons', right=kit.band_button(t, 'plus', 'New lesson'))
    body = kit.section_label(t, 'This week') + kit.list_group(t, [
        dict(title='Class · 28 October', meta='2 videos · 3 figures', trailing=kit.chevron(t), href='#')])
    return kit.page(t, header, body, tab='Lessons')

html, w, h = kit.artboard('Lessons', 'One line on what this board shows.',
                          [('Lessons', 'the list', lessons, 'bachata')])
kit.write('/…/canvas/project/Lessons.dc.html', html)
```

Run: `timeout 180 nix shell nixpkgs#python3 -c python3 -I script.py`.
Preview: `tools/snap.sh IN OUT W H`, or `gen/kit/shoot.sh IN PREFIX WIDTH [SLICE_H] [SCALE]`
for tall boards (prints the measured height, writes slices).

## Themes

`kit.THEMES[(dance, mode)]`, dance `'salsa' | 'bachata'`, mode `'light' | 'dark'`.
`kit.MEDIA[dance]` = the full-screen video player palette (black ground, `glass`,
`glass_line`, `track`, `section`, `top_scrim`/`bottom_scrim`); usable as `t`.
`kit.theme(dance, mode)` accepts `'media'` too. Take EVERY colour from `t`:
band, band_ink (cream), band_small (text < 24px on the band), band_track, ground, surface,
raised, sheet_bg, field, hairline, field_line, ink, ink2, muted, chevron, accent,
accent_text (small accent text), accent_soft, accent_pressed, accent_soft_pressed,
on_accent, status, done, on_done, done_soft, danger, on_danger, danger_soft, warn,
warn_soft, focus, focus_halo, chip, chip_ink, step, tab_bg, tab_line, tab_tint,
pressed, scrim, shadow, band_shadow, disabled_bg, disabled_ink, skeleton,
switch_off, thumb, grabber, inverse_bg, inverse_ink, inverse_accent.
`kit.audit(t)` measures 28 contrast pairs; all four themes pass.

Type: `kit.ts(name, color)` → CSS for `display` (46 Bricolage), `display_s` (30),
`hero` (25), `headline` (22), `number_l`, `title` (16/700), `body`, `subtitle` (15/600),
`button`, `number`, `meta` (13/400), `label` (13/700), `chip`, `caption`.
`kit.SPACE`, `kit.RADII`, `kit.FONTS_LINK`, `kit.SR` (visually hidden).

## artboard()

`kit.artboard(title, sub, screens, per_row=3, doc_title=None, dance=None)` →
`(html, width, height)`. `screens`: tuples `(name, note, fn[, dance])` or dicts
`{name, note, fn, dance}`. Each `fn(t)` is drawn with the light and the dark theme
of its dance, side by side, caption under the pair. 3 pairs per row = 2772px wide;
height = 232 + rows × 928 + (rows−1) × 72 (one row = 1160). The root div and `$preview`
are exactly that size. `kit.document(body, w, h, title)` for custom layouts.

## Conventions

- Content must come from the REAL app screen (read the route in
  `src/routes/[dance]/…`); don't invent features. No dance icon or dance name in screens.
- Ids only through `kit.uid()` (the kit does this): screens are drawn twice per board.
- A row is EITHER a link (`href`) OR holds one button (log +, switch) — never both.
- Small accent text uses `accent_text`; small text on the band uses `band_small`.
- Focus = `kit.ring(t)` (2px ring + 4px halo), or `ring(t, on=bg)` around filled controls.
- Disabled = `disabled_bg` fill + `disabled_ink` text, plus the `disabled` attribute.
- Pushed screens: `left=band_button(t, 'back', 'Back to <parent>')`, no tab bar.
- Danger is crimson (light `#c4183c`, dark `#ff5c7a`) so it stays apart from salsa's red-orange accent.

## Screens

`screens/*.py` drew the per-area screen boards ("Screens · …" on the canvas),
one file per area; `examples.py` holds the sample data and shared pieces they
use. Each screen is a function returning HTML built from `kit.py`'s tokens and
components, so the exact markup, spacing and copy for any screen is readable
there. They were run from a scratch directory (`gen/kit` beside
`gen/screens`); here they are reference only.
